DEMO SEQUENCE — PRIVATE REPORT / REAL SUPABASE
Keep this file separate from the shared app window. Nothing is displayed as
speaking notes inside the app.

1. Sign in as Alice, then Download my report.
   "This looks like a normal account page. The download is an actual action:
   the browser sends my access token to Supabase, which checks it and returns
   only my report. The password was checked at login, not on every download."

2. Open Session & access tools. Request report without a token.
   "This sends the same request without the Authorization header. Here is the
   actual HTTP response. The server refused to return a report. Hiding the
   download button alone would not be enough; this check happens at Supabase."
   Show HTTP 401 AND the earlier successful download. An invalid key can also
   cause 401, so confirm the unchanged token works before drawing a conclusion.

3. Show Payload. Find sub, email, exp and iss. Reload.
   "These claims are readable, but that does not make them trustworthy. The
   API verifies the token. The browser stores a session so I can reload without
   entering my password again. The next download still requires authorization."

4. Capture token > Sign out > Replay copied token.
   "A bearer token works through possession. This copy is held separately in
   memory. Signing out removes the browser session and revokes refresh access,
   but an access JWT may still work until its expiry. Let's read the response."
   If accepted: it returned Alice's report. If rejected: show its error; do not
   claim natural expiry unless the real exp and response support that.

5. Sign in as Alice again. Verify Bob's note using his password, then run checks.
   "A copied token can act as Alice in this demo. It cannot become Bob's valid
   token just by changing the identity or expiry: that breaks the signature.
   Bob has a confirmed note, but Alice's unchanged token cannot read it."
