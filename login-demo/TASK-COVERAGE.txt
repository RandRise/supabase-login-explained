WEEKLY TASK COVERAGE — STUDENT QUIZ VERSION

WHAT HAPPENS TO THE PASSWORD?
Observed: password sent once to Supabase Auth over HTTPS; page clears the input.
Explained from Supabase docs: salted bcrypt hashes, not plaintext passwords.
We do not inspect server password hashes or claim the browser hashes it first.

WHAT IS A SESSION / TOKEN?
Observed: login returns an access token, refresh token and user; subsequent
quiz requests attach Authorization: Bearer ... with no password.
Explained: the access JWT has claims/expiry; the refresh token obtains new
access tokens. This app restores stored sessions but does not auto-refresh.

WHERE IS IT STORED / HOW ARE YOU REMEMBERED?
Observed: team3-student-session-v1 in this origin's localStorage; reload
restores the session and fetches results. Swagger uses the same origin to
copy the portal session into its own in-memory authorization state.
This is one explicit storage design, not how every website handles sessions.

FIND AND DECODE THE TOKEN
Observed: locate the stored session in DevTools; Swagger decodes selected JWT
claims locally. Reading claims is not signature verification.
Observed live API: changing sub without a new signature is rejected with 401.

DO YOU NEED THE TOKEN?
Observed: same protected quiz/result RPC with no bearer -> 401, valid bearer
-> success. The public questions deliberately remain accessible without it.

AUTHENTICATION VERSUS AUTHORIZATION
Observed: valid Alice bearer asking for Bob's result -> 403.
Direct table SELECT uses RLS and returns [] for another owner's records.
Database owner checks remain effective even when bypassing the website UI.

WHAT COULD AN ATTACKER DO WITH A STOLEN ACCESS TOKEN?
Observed in the dedicated test project: copied unexpired Alice token reads
Alice's result and submits another attempt as Alice, even after portal-style
local logout. The API cannot tell a legitimate holder from a thief holding
that same bearer.
It cannot derive the original password from the JWT, become Bob by editing
sub, or bypass the configured RLS/grants. Other account-management operations
depend on provider policy; do not claim bearer theft can never affect them.
Natural expiry and refresh-token theft are explained, not timed/live-tested.

GOOGLE SIGN-IN WITHOUT YOUR GOOGLE PASSWORD
Teammate's section. No live OAuth integration in this student app.

ARTIFACT / DEMO
Responsive student portal, real Supabase Auth and Postgres RLS, server-calculated
quiz scores, real Swagger UI, source code, setup instructions and demo runbook.
Only invented data; repeated attempts allowed. This is not an anti-cheating exam.
